# Fuzzing `sequoia-openpgp`

This directory contains `cargo-fuzz` targets for `sequoia-openpgp`.

The targets are intentionally small and focused. Each target expects inputs
appropriate to its corresponding corpus directory, and corpus directories
should contain homogeneous inputs for the target they serve.

> The **repo-wide** fuzzing tooling — the `./fuzz-all.sh` runner, its
> replay/timed modes, the seed-commit policy, and the CI jobs — is documented in
> [`doc/fuzzing.md`](../../doc/fuzzing.md).  This file covers only the
> `sequoia-openpgp` targets and how to run them individually.

## Prerequisites

Install `cargo-fuzz` if needed (it requires a nightly toolchain):

```bash
cargo install cargo-fuzz
```

## Running individual targets

Run targets from the `openpgp/` directory (not from `openpgp/fuzz/`), with the
nightly toolchain. On macOS with homebrew you may need to set the path prefix:

```bash
export PATH="$HOME/.cargo/bin:$PATH"
```

By default, `cargo-fuzz` uses `fuzz/corpus/<target-name>` as the corpus
directory for a target:

```bash
cargo fuzz run cert_from_bytes
cargo fuzz run key_packet_from_bytes
```

Additional corpus directories can be supplied after the target name:

```bash
cargo fuzz run key_packet_from_bytes \
  fuzz/corpus/key_packet_from_bytes \
  fuzz/corpus/cert_from_bytes \
  -- -max_total_time=30
```

To limit execution time during local experimentation, pass libFuzzer options
after `--` (`-max_total_time` is in seconds):

```bash
cargo fuzz run key_packet_from_bytes -- -max_total_time=30
```

## Seed corpora

The openpgp seed corpora are (re)generated by `openpgp/fuzz/generate-seeds.sh`
(run automatically by `./fuzz-all.sh` in replay mode), which combines two
complementary sources:

```bash
# 1. Fresh, self-consistent objects (certs, key packets, signed/encrypted/
#    cleartext messages) built from a throwaway key, covering all targets:
cargo run -p sequoia-openpgp --example generate_key_seeds

# 2. Real-world fixtures copied from openpgp/tests/data:
bash openpgp/fuzz/scripts/populate-parser-corpora.sh
```

Both are safe to run repeatedly. The generated inputs are valid OpenPGP objects
that give fuzz targets meaningful starting points to mutate from.

Run standalone (as above), these write into the in-tree `fuzz/corpus/`.  When
`./fuzz-all.sh` runs the hook it sets `FUZZ_CORPUS_OUT` to redirect them to an
out-of-tree corpus, leaving the source tree untouched.  See
[`doc/fuzzing.md`](../../doc/fuzzing.md) for the corpus-directory model and what
belongs in git (generators and regression reproducers) versus not (bulk corpora).

## Adding a new openpgp fuzz target

- Keep the target narrowly focused.
- Create a matching corpus directory under `fuzz/corpus/`, and extend
  `generate-seeds.sh` (or the `generate_key_seeds` example) to seed it.
- Prefer structured seed inputs over large random corpora.
- Ensure the target runs from `openpgp/` using `cargo fuzz run`.
- Corpus directories should match the expectations of the target: keep seeds
  small and homogeneous.
